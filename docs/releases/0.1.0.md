# PQC Migration Lab 0.1.0

The first tagged reference release of PQC Migration Lab: an Apache-2.0 project for exploring application-level post-quantum signature migration in a working Java integration.

## Included

- Ed25519 and ML-DSA-65 signing and verification, with JDK/Bouncy Castle interoperability and public reference vectors.
- DSSE framing and wire handling that preserve the original payload bytes.
- A Spring Boot publisher and receiver with classical, shadow, both-required and PQC-required verification policies.
- Signed issuer, audience and freshness checks, transactional idempotency and durable receipts.
- Persistent encrypted publisher keys, atomic generation rotation, bounded overlap and revocation that applies to retries without deleting historical acceptance records.
- An English React/TypeScript workbench for real Java observations, public key state, fault scenarios and receipt inspection.
- An isolated one-command migration demonstration with public JSON/Markdown reports and checksum manifests.
- Independent JMH measurements with explicit warm-up, forks, samples, uncertainty and operation boundaries.
- Three original application screenshots, a guided walkthrough, threat model, architecture decisions and documented fixture provenance.

## Verification

The release is checked with JDK 25 and Node.js 24.14 in the 24 LTS line. Its required checks cover:

- Strict Java compilation, Javadoc, formatting, architecture rules and per-module line-coverage gates.
- Java and frontend unit tests, strict TypeScript and the production workbench build.
- The cryptographic interoperability probe and the four-policy HTTP demonstration.
- The isolated migration story, including its two disk-only runtime reconstructions.
- The actual forked JMH smoke harness, without comparative performance thresholds.
- Distributable Java archives and their included legal files.

The [GitHub Actions workflow](https://github.com/gbalazsfalvi/pqc-migration-lab/actions/workflows/verify.yml) records the actual Windows and Linux results. Smoke timings and functional HTTP timings are not comparative benchmark evidence.

## Run the release

Check out tag `v0.1.0`, then run the isolated demonstration on Windows:

```powershell
.\lab.ps1 migration-demo
```

On Linux or macOS, with JDK 25 selected:

```sh
npm ci --prefix workbench --no-audit --no-fund
./gradlew migrationDemo --console=plain
```

For the interactive workbench, run `lab.ps1 serve` on Windows or `./gradlew :integration-app:bootRun` on Linux/macOS, then open `http://127.0.0.1:8781/`.

## Experimental scope

Both Spring Boot contexts and their real loopback HTTP servers run in one JVM. The example uses synthetic software-release events and assumes the local OS account, providers and clock are trusted.

This release demonstrates application-level migration. Production operator authentication, remote trust distribution, production key custody and hosted operation require separate design and verification. No post-quantum TLS, FIPS validation or NIST approval is claimed. APIs may evolve before version 1.0.
