# PQC Migration Lab 0.2.0

This reference release completes milestones 06A and 06B: independent publisher
and receiver services, a local Docker Compose deployment and a four-phase
migration of the live receiver requirement.

## What changed

- Separate publisher, receiver and initialization JVM roles, alongside the
  retained one-JVM reference launcher.
- Multi-stage Docker builds with pinned images, distinct non-root service users,
  separate persistent volumes and loopback host publications.
- Public-only trust snapshots coordinated by OS file leases, with pending-write
  fences and authenticated recovery. The receiver never mounts publisher keys
  or its wrapping secret.
- A 06A lifecycle demonstration covering actual receiver termination, gateway
  failure, independent role restarts and durable receipt reuse.
- A 06B deployment rehearsal:
  CLASSICAL_ONLY → SHADOW_PQC → BOTH_REQUIRED → PQC_REQUIRED.
  One publisher, unchanged trust and ledger, and three original sender profiles
  cross all four phases.
- Immutable first-acceptance evidence kept separate from current enforcement.
  An earlier classical acceptance cannot bypass a later PQC requirement.
- Portable HTML, Markdown, schema-2 JSON, exact public HTTP bodies and checksum
  evidence, with an actual reviewed example and an original report screenshot.

The four-phase target keeps PQC mandatory while retiring the classical
requirement; it intentionally admits PQC-only senders rejected by BOTH_REQUIRED.
Policy changes are controlled receiver deployments, not HTTP policy overrides.

## Reproduce the release

Check out tag v0.2.0. For the interactive deployment:

    docker compose up --build --detach --wait

Open http://127.0.0.1:8781/. Docker alone builds Java and the React workbench.
For native demonstrations, select the JDK 25 and pinned Node/npm prerequisites
documented in the [README](../../README.md).

Windows:

    .\lab.ps1 migration-demo
    .\lab.ps1 rehearsal-demo
    .\lab.ps1 compose-rehearsal

Linux/macOS:

    npm ci --prefix workbench --no-audit --no-fund
    ./gradlew migrationDemo rehearsalDemo --console=plain
    ./gradlew composeRehearsalDemo --console=plain

The automatic demonstrations own fresh state and clean only their own runtime
resources. Ordinary interactive Compose down preserves its named volumes.
The earlier v0.1.0 tag and legacy-migration-demo command remain available.

## Verification and downloadable evidence

The 16 November 2026 milestone verification passed 228 Java tests, 17 frontend
tests, 53 interoperability checks and 23 original HTTP-demo expectations.
The native 06A story passed 108 assertions over 32 HTTP attempts.
Native and actual Compose 06B rehearsals each passed all four phases,
165 assertions and 49 HTTP attempts.

Release verification keeps strict compilation, Javadoc, formatting, architecture,
dependency checksums and per-module 90% line coverage. The Windows/Linux workflow
must pass for the release commit and tag before the GitHub release is published.
Compose remains an explicit local verification command. JMH smoke checks verify
the harness; no new comparative performance result is claimed.

The release adds an additional regression that verifies every committed example
artifact against its original byte manifest, bringing the Java total to 229.
Git attributes preserve those exact bytes and keep the Unix Docker launcher
LF-compatible across Windows checkouts.

The GitHub release provides:

- pqc-migration-lab-0.2.0.jar: executable JAR with the bundled English workbench
  and legal notices; requires Java 25.
- pqc-migration-lab-0.2.0-example-evidence.zip: the exact reviewed public
  [Compose example](../evidence/README.md), readable without running Java.
- SHA256SUMS: byte digests for the two downloadable assets.
- GitHub's tagged source archives.

The example was captured during the milestone verification. It is a dated
observation, not a live report; fresh executions have different IDs and keys.
Unsigned checksums identify bytes and do not independently authenticate a bundle.
