## ML-DSA-65 public verification fixtures

Three small fixtures are extracted from the US National Institute of Standards and Technology's [ACVP-Server repository](https://github.com/usnistgov/ACVP-Server).

Pinned source commit: `a7f283cdc87d2d6dd93c1bac59e5622c5f9f8324`.

| Local fixture                   | Upstream dataset                                         | Group | Case | Expected verification |
| ------------------------------- | -------------------------------------------------------- | ----: | ---: | --------------------- |
| `ml-dsa-65-valid-3.properties`  | ML-DSA-sigGen-FIPS204/internalProjection.json            |     3 |   44 | Valid                 |
| `ml-dsa-65-valid-15.properties` | ML-DSA-sigGen-FIPS204/internalProjection.json            |    15 |  216 | Valid                 |
| `ml-dsa-65-invalid.properties`  | ML-DSA-sigVer-FIPS204/prompt.json + expectedResults.json |     3 |   39 | Invalid               |

All selected cases use the external pure ML-DSA-65 interface with an empty context. The valid cases come from deterministic and hedged signing groups respectively; the tests verify their published signatures without reproducing their signing randomness.

The checked-in files retain public key, message, signature, source identity and expected verification result only. Upstream secret keys and random signing inputs are deliberately omitted.

Each fixture embeds its complete immutable upstream URL. The verification code converts the raw public key into SPKI using Bouncy Castle's public key specification API, then independently verifies the answer with both providers.

The data is attributed to NIST. The complete notice from the pinned upstream README is retained in [NIST-ACVP-NOTICE.txt](THIRD_PARTY_LICENSES/NIST-ACVP-NOTICE.txt). Consult [the upstream repository](https://github.com/usnistgov/ACVP-Server/tree/a7f283cdc87d2d6dd93c1bac59e5622c5f9f8324) for provenance. Using these fixtures does not confer NIST validation or approval.

The local adaptation retains selected public keys, messages, signatures and verification outcomes in properties files, with upstream source identifiers. Secret keys and signing-randomness fields are omitted. This adaptation and notice retention were reviewed on 13 November 2026; no NIST implementation code is included.

## Dependencies and build tooling

Third-party libraries are consumed from their published artifacts. Their published licences continue to apply. Exact Java versions and resolved dependencies are recorded in the version catalog and Gradle lockfiles. Frontend versions and integrity hashes are recorded in `workbench/package-lock.json`.

Gradle wrapper scripts and the wrapper JAR are generated by Gradle and retain their upstream notices.

The benchmark module consumes [OpenJDK JMH](https://github.com/openjdk/jmh/tree/1.37) 1.37 and its annotation processor from Maven Central. JMH is distributed under GPL version 2 with the Classpath Exception; see [the upstream licence](https://github.com/openjdk/jmh/blob/1.37/LICENSE). The module's generated timing loops are created by that processor. The benchmark methods and report implementation in this repository are project code; no JMH sample source is copied.
